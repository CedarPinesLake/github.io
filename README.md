# Cedar Pines Lake Guest Guide

## Purpose

This repository contains the guest guide website used by the QR codes placed in all three Cedar Pines Lake short-term rental properties.

The guide is intended to provide guests with helpful, current information about the local area while quietly showcasing our other rental properties. Rather than serving as a tourism website, it is an extension of the hospitality our guests experience during their stay.

Our goals are to:

- Help guests enjoy their visit.
- Reduce repetitive questions.
- Provide useful local recommendations.
- Encourage repeat stays.
- Introduce guests to our other nearby rental properties.

---

## Design Philosophy

Keep it simple.

This project intentionally uses plain HTML, CSS, and minimal JavaScript.

There is no framework, build process, package manager, or unnecessary complexity.

The website should remain understandable and maintainable by anyone with basic web development experience.

If a future enhancement requires significant complexity, we should first ask whether the additional complexity genuinely benefits the guest experience.

---

## Guiding Principles

### Guest First

Every change should improve the guest experience.

Before adding any feature, ask:

> **Does this genuinely help a guest?**

If the answer is no, it probably doesn't belong.

---

### Simplicity Wins

Prefer straightforward solutions over clever ones.

Readable code that is easy to maintain is more valuable than sophisticated code that is difficult to understand.

---

### Authentic Recommendations

Recommendations should feel like they came from the host—not from a tourism bureau.

Where possible, include personal favorites and practical advice instead of generic marketing descriptions.

---

### One Source of Truth

Information should exist in one place whenever possible.

Avoid duplication that creates unnecessary maintenance.

---

### Incremental Improvements

Make small, tested improvements rather than large rewrites.

Each commit should leave the project in a working state.

---

## Development Workflow

Development should always occur locally.

Typical workflow:

1. Fetch Origin
2. Pull latest changes
3. Make changes locally
4. Test locally
5. Commit with a meaningful message
6. Push to GitHub
7. Verify the published GitHub Pages site

Direct edits on GitHub should be reserved for emergency fixes.

---

## Coding Standards

- Use relative paths.
- Use descriptive file names.
- Keep HTML semantic and readable.

## Project Goals

The website should become a digital concierge for our guests.

Rather than being a long list of links, it should help guests quickly answer questions such as:

- Where should we eat?
- Where can we buy groceries?
- What is there to do nearby?
- What can we do if it rains?
- What local attractions are worth visiting?
- Where are practical services such as pharmacies or urgent care?

The guide should feel welcoming, helpful, and easy to navigate on a mobile phone.
